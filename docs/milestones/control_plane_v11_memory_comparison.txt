=== Interpretation ===
The +13,776-byte DIRAM delta is the resident control core:
  Session            13,216 B  (parser 4,784 + 8 KiB TX ring + counters)
  ProductState          400 B
  UART transport/task overhead
matches sizeof(Session)+sizeof(ProductState) measured on host, confirming the
static footprint is exactly the control objects and nothing else.

The .data increase (+13,160) is the initialized static control objects; the
remaining +392 .bss is ancillary. No DSP object size changed.

=== Runtime memory (PENDING HARDWARE) ===
The following require a booted device and could not be measured here:
  internal free heap after boot (VoxLink OFF / ON)
  largest internal free block
  PSRAM free / largest PSRAM block
  VoxLink task stack high-water mark
  audio task stack high-water mark

UART driver ring buffers (rx 4096 B, tx 8192 B) are allocated from the heap at
server start and are therefore NOT included in the static delta above; they are
conditional on the server actually starting (pins assigned).

=== DIRAM pressure note ===
Enabled DIRAM usage is 89.8% (58,777 B remaining). This is acceptable but has
less headroom than the disabled build (87.41%). No memory was migrated to PSRAM
because the static control buffers are small and the pressure source is the
frozen DSP, not VoxLink. If runtime measurement shows allocation problems, the
first candidates are the TX ring (8 KiB) and parser queue, per the v1.1 plan;
audio/DMA/DSP memory must not be moved.
